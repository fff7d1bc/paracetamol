# llama.cpp maintainer acceptance

This opt-in developer tool runs versioned synthetic regressions through the
ordinary Paracetamol gateway. It is not a managed application, agent client,
replacement inference engine or public `benchmark` command. It never starts,
restarts or stops a gateway/backend, installs models or changes host policy.
It owns only its private evidence and exact-owned CPU grading containers.

Use [llama.cpp maintenance](../../docs/llama-cpp-maintenance.md) for the current
accepted engine and open issues, and
[source-update acceptance](../../docs/testing-and-release.md#llamacpp-source-update-acceptance)
for the complete update gate. A passing selected suite is not full upgrade
acceptance. Operator/state fixtures, image/CPU checks, other API endpoints and
applicable hardware acceptance remain separate requirements.

The kit's executable test logic, generators, prompts, independent oracles and
grading inputs live in this directory, not in a previous experiment's
`build/` path. Private results are disposable build artifacts, not the only
copy of the runner. Historical experiments and their failures remain unchanged.

## Bootstrap from a clone

Building the helper needs the normal Linux host development prerequisites:
Go 1.26, GNU Make, a C compiler and glibc development headers. It does not
require an existing `build/` tree, Podman, model weights or a GPU:

```bash
make llama-acceptance
CHECKER=./build/linux-amd64/bin/llama-acceptance
"$CHECKER" --help
"$CHECKER" self-test --source-only
```

The example binary path is for Linux amd64. Make keeps platform-qualified
binaries, module state, caches and temporary files below checkout `build/`.
`--source-only` validates tracked fixture identities and source-level oracle
controls. It starts no container and makes no inference request. It does not
claim that an executable grading sandbox or model has passed.

Generated-code grading additionally needs working rootless Podman and the
explicitly built Linux amd64 CPU grading image. Prepare its tracked recipe:

```bash
"$CHECKER" prepare-grader --out build/llama-grader-recipe
podman build -f build/llama-grader-recipe/Containerfile \
  -t localhost/paracetamol-experiment:llama-grader-v1 \
  build/llama-grader-recipe
podman image inspect --format '{{.Id}}' \
  localhost/paracetamol-experiment:llama-grader-v1
```

`prepare-grader` writes a new recipe directory; it downloads and builds
nothing. The separate build is networked preparation and may need the pinned
base image and signed package repositories. Keep it out of inference timings.
Set `GRADER_IMAGE` to the full immutable image ID printed by inspection, then
exercise trusted solutions and deliberately wrong implementations:

```bash
"$CHECKER" self-test --grader-image "$GRADER_IMAGE" \
  --out build/llama-grader-selftest
```

The recipe pins the Ubuntu base digest, Go archive/hash and Python package
versions, and retains its installed package manifest. It does not promise
byte-identical distro dependency archives. Missing pins or unavailable
packages block preparation; do not substitute the host toolchain or loosen
versions. Review provenance and licensing in
[coding provenance](internal/coding/PROVENANCE.md) before changing the recipe.

The grader has no network or GPU devices, a read-only root, no capabilities,
`no-new-privileges`, bounded tmpfs, 2 GiB memory, two CPUs, 128 PIDs and a
120-second execution lifetime. These are untrusted-code limits, not inference
deadlines. Only private staged inputs are mounted read-only. Expected answers
stay in the trusted Go controller. The tool neither installs/relabels a host
toolchain nor mounts the checkout, home directory or container socket into
generated code. A confinement, compiler or cleanup failure blocks grading.
Containers reduce execution risk; they are not a proof against kernel bugs or
adversarial manipulation of same-process ownership checks.

## Prepare matching-source native probes

Native operator/state gates are separate from gateway answer oracles. Generate
a recipe from the **current** production Containerfile and tracked fixtures:

```bash
"$CHECKER" prepare-native --out build/llama-native-recipe --upstream-tests
./paracetamol build runtime
podman build --pull=never --layers --target llama-acceptance-native \
  -f build/llama-native-recipe/Containerfile \
  -t localhost/paracetamol-experiment:llama-native .
podman image inspect --format '{{.Id}}' \
  localhost/paracetamol-experiment:llama-native
```

`prepare-native` only writes the new recipe and `prepare-native.json`; it
downloads, builds and executes nothing. It refuses changed production-stage,
source/install or fixture contracts. Review those boundaries after an upgrade
rather than bypassing a guard, editing generated bytes or silently overriding
build arguments. Repeat preparation in the matching source checkout for each
baseline/candidate image.

The diagnostic target inherits the normal production runtime and compiles
five probes against that builder's exact patched headers and installed
libraries: `test-qwen4exp-state`, `test-topk-moe-lifetime`,
`test-qwen4exp-conv-rollback`, `test-qwen4exp-active-pool` and
`test-recurrent-state-clear`. No GPU is exposed during compilation. The
production builder's existing CPU build gates remain in effect. Optional
`--upstream-tests` also compiles upstream `test-backend-ops` and
`test-llama-context`, without reconfiguring/rebuilding the production
libraries. Preparing or building this image is not execution of those GPU
gates or model inference acceptance.

Set `NATIVE_IMAGE` to the inspected full diagnostic image ID. Export `/opt/probe`
from an exact temporary container without starting it:

```bash
mkdir build/llama-native-probes
EXPORT_ID=$(podman create --pull=never --network=none --read-only \
  --cap-drop=ALL --security-opt no-new-privileges "$NATIVE_IMAGE")
podman container inspect "$EXPORT_ID"
podman cp "$EXPORT_ID":/opt/probe/. build/llama-native-probes/
podman rm "$EXPORT_ID"
```

Check each command before proceeding; remove only that newly created exact
container ID. The exported compiler/source, fixture/binary, CMake and
`installed-libraries.sha256` manifests identify the compile closure. Compare
the installed library hashes with `/usr/local/lib` in the intended **normal**
image before binding the exported probes read-only into it. A matching tag or
upstream commit is insufficient, and `common_params` has no stable ABI.

Execute the applicable probes explicitly using the commands and expected
case/round counts in
[native source-update gates](../../docs/testing-and-release.md#native-build-regression-gates)
and the following pool/reset and fast-state sections. GPU runs need normal
rootless, read-only, network-none confinement, only `/dev/kfd` and the exact
selected render node, and matching receipt-verified model mounts when needed.
Record actual execution/results separately from preparation. Keep diagnostic
image IDs distinct; use the final normal image for performance and gateway
acceptance. Kernel activation still needs an independent trace where required.

### Execute exported probes

Confirm `podman info --format '{{.Host.Security.Rootless}}'` reports `true`.
For the weight-free lifetime and convolution fixtures, set `NORMAL_IMAGE_ID`
to the normal runtime's full inspected ID, `RENDER_NODE` to the exact accepted
device and `PROBES` to the absolute exported probe directory. With no other
model work running:

```bash
(
  set -eu
  for PROBE in test-topk-moe-lifetime test-qwen4exp-conv-rollback; do
    podman run --rm --pull=never --network=none --read-only \
      --cap-drop=ALL --security-opt no-new-privileges --userns keep-id \
      --device /dev/kfd --device "$RENDER_NODE" \
      --env HOME=/tmp --env XDG_CACHE_HOME=/tmp/cache \
      --env PARACETAMOL_QWEN4EXP_QSA_GRAPH=1 \
      --env PARACETAMOL_QWEN4EXP_QSA_KERNEL=1 \
      --tmpfs /tmp:rw,nosuid,nodev,size=512m \
      --volume "$PROBES:/opt/probe:ro,Z" \
      --entrypoint /usr/bin/env "$NORMAL_IMAGE_ID" \
      -u GGML_CUDA_ENABLE_UNIFIED_MEMORY "/opt/probe/$PROBE"
  done
)
```

These two programs require `ROCm0` internally. Check each exit status and
retain its output before proceeding. Require eight passing lifetime cases
with nonzero valid dependency callbacks, then
`CONV_ROLLBACK_SUMMARY cases=40 rounds=160 mode=ROCm-matcher-required PASS`.
The convolution program's `--cpu` switch is not a substitute. A CPU result,
zero cases, unexpected skipped cases or an unavailable ROCm backend cannot
pass GPU acceptance. Do not run these commands against a merely similarly
named diagnostic library set.

### Numerical case manifest

With `--upstream-tests` prepared, the same confinement can run the complete
maintained Qwen/QSA numerical group:

```bash
podman run --rm --pull=never --network=none --read-only \
  --cap-drop=ALL --security-opt no-new-privileges --userns keep-id \
  --device /dev/kfd --device "$RENDER_NODE" \
  --env HOME=/tmp --env XDG_CACHE_HOME=/tmp/cache \
  --env PARACETAMOL_QWEN4EXP_QSA_GRAPH=1 \
  --env PARACETAMOL_QWEN4EXP_QSA_KERNEL=1 \
  --tmpfs /tmp:rw,nosuid,nodev,size=512m \
  --volume "$PROBES:/opt/probe:ro,Z" \
  --entrypoint /usr/bin/env "$NORMAL_IMAGE_ID" \
  -u GGML_CUDA_ENABLE_UNIFIED_MEMORY /opt/probe/test-backend-ops \
  test -b ROCm0 -o 'QSA_.*,QWEN_.*'
```

This selects correctness testing against CPU references, not `perf` or
`support` mode. These commands bypass the normal entrypoint, so they enable
the normal QSA kernel/graph policy explicitly and unset unified-memory mode
like the managed Flash-Next child. Environment enablement establishes
eligibility, not dispatch. Save per-case results and unsupported/skipped
cases, not just the final exit code. The expected case manifest belongs to the selected
source, not whichever count a candidate happens to print. Additional
upstream `TOPK_MOE`, GDN and cache/state groups remain separate gates from
these maintained custom groups. Review the pinned test source and expected
case list before running a changed source tuple. Do not use grouped regexes
containing `(` with `-o`; the pinned parser treats those as literal full-case
selectors and can silently select no cases.

### Missing GPU poisoned-reset coverage

The exported `test-recurrent-state-clear` currently has only a CPU mode.
It can check the real helper's poison/reset semantics, but does not supply
the separately required GPU-backed poisoned-reset gate. The full-model state
probe covers different save/restore behavior and is not that missing test.
Keep this coverage BLOCKED until an explicit GPU fixture is implemented and
qualified against both the corrected helper and a rejected old-helper
control. Do not reinterpret a CPU PASS as GPU coverage or silently drop that
requirement from a refresh campaign.

## Prepare an inference comparison

Run the checker on the inference host. Both gateway and private native probes
use numeric loopback HTTP addresses. There is no remote-host shortcut,
experimental proxy or alternate sampler implementation.

The inference host also needs `journalctl` and permission to read its current
boot's kernel journal. Preflight requires an actual nonempty boot/cursor;
missing visibility is BLOCKED, not a disabled monitor. During checks, the
read-only guard examines only entries after that cursor for GPU faults,
resets, ring timeouts, SVM mapping failures, nonfinite/hardware errors and
llama.cpp process segfault/OOM reports. Lost visibility, cursor loss, overflow
or a reboot also block the run. Polls and the final cursor drain are bounded
metadata probes, not inference deadlines. Only filtered reason codes,
cursor/boot/time observations are saved privately, never unrelated raw kernel
messages. The tool does not use sudo or change journal/device permissions.

An independent available-RAM guard stops the suite below 8 GiB. Keep both
guards enabled; do not change host memory, swap, kernel or power policy to
force a run through them. Lack of required capacity or read permission is a
prerequisite to resolve explicitly, not model-quality evidence.

Before inference, arrange a free target GPU, exact render node, sufficient
capacity and permission to run this bounded campaign. Build the accepted
baseline and candidate locally from their immutable recipes. Retain distinct
full image IDs, patched source-tree IDs and source revisions. A tag does not
identify a patched binary. Do not restart somebody else's workload, disable
guards or modify swap, firmware, driver or power policy to make tests fit.

Install the selected regular Flash-Next content and DFlash2 control through
the normal content installer. All required model/projector/draft bytes need
current receipts and their normal license agreements or explicit
`NOASSERTION` acknowledgment. The checker neither downloads content nor
acknowledges licenses. See [content guidance](../../docs/guides/content.md).

Start a dedicated ordinary gateway explicitly, using its reviewed ROCm policy
and four slots. Consult `./paracetamol run gateway --help` and the
[gateway guide](../../docs/gateway.md); do not expose native backend ports.
Warm the selected model with one bounded ordinary request so its native child
and effective arguments are observable. Wait for the gateway to be idle before
preflight. Use `podman ps --no-trunc` and exact container/image inspection to
identify the already-running gateway-owned backend. The checker revalidates
ownership, immutable image identity, model mounts, native policy and template.

The current fixture policy requires ROCm, a 262144-token shared pool, four
slots, F16 K/V and batch/microbatch 2048. The speculative arm requires managed
greedy DFlash2 depth three; the plain arm must disable speculation. Changing
these is a separately reviewed fixture policy change, not a workaround for a
candidate failure. Actual cache occupancy and newly evaluated tokens are
observations, not inferred from those configured capacities.

Set the following shell variables to your inspected values: `GATEWAY_URL`
(for example `http://127.0.0.1:7455/v1`), `CONTAINER_ID`, `IMAGE_ID`,
`DATA_DIR` (the existing absolute data root) and `GRADER_IMAGE`. These names
are local placeholders, not a saved configuration or provenance assertion.
Set `PREFILL_TOLERANCE` to the deliberately chosen time-per-token regression
percentage before running either timed arm; do not select it from the
candidate's result.
If gateway authentication is enabled, add
`--gateway-api-key-file /absolute/private/gateway.key` to preflight/check.
The checker never saves the key. Keep real addresses, native URLs, credentials
and private paths out of tracked documentation and public result summaries.

```bash
MODEL=unsloth-qwen3.8-flash-next-125b-a6b-ud-q4-k-xl
"$CHECKER" preflight --gateway-url "$GATEWAY_URL" \
  --container-id "$CONTAINER_ID" --image-id "$IMAGE_ID" \
  --data-dir "$DATA_DIR" --model "$MODEL"
"$CHECKER" check --gateway-url "$GATEWAY_URL" \
  --container-id "$CONTAINER_ID" --image-id "$IMAGE_ID" \
  --data-dir "$DATA_DIR" --model "$MODEL" \
  --suite all --grader-image "$GRADER_IMAGE" \
  --prefill-regression-percent "$PREFILL_TOLERANCE" \
  --out build/llama-baseline-plain-1
```

`preflight` is read-only: no inference, model loading, output creation or
grading execution. Its prerequisite is an already-loaded native child.
`check` needs a fresh output directory below checkout `build/`; it refuses
reuse. The default suite is only `short`, and the default model is the
`-dflash2` identity, so spell both explicitly in acceptance commands.

For a source/ROCm update, run the complete required matrix against both
baseline and candidate, with regular `MODEL` and `MODEL-dflash2` selected
separately. Warm and inspect each selected child before its run. Use unique
output paths and accurate image/container IDs for every arm. Stop only the
gateway you started, through its normal lifecycle, when switching images.
Neither the checker nor comparison owns that transition.

| Suite | Bounded coverage |
| --- | --- |
| `short` | Six thinking-off replay controls, low/medium/xhigh effort, nested tool calls and complete JSON/SSE round trips. |
| `lifecycle` | A resident history reused after second-slot work, four slot-directed workers, both cancellation paths and synthetic media/history changes. Runs independently of near-limit retrieval. |
| `coding` | CPU grader self-test and original Go/Python generated-code cases with the predeclared attempt policy below. |
| `history` | Measured near-limit distributed retrieval, exact repeat, isolated edit and true appends preserving reasoning. |
| `prefill` | Measured cold 32K prefill and a versioned multi-slot conditioning sequence followed by cold 16K work. |
| `all` | All five families, starting with short and lifecycle checks and stopping further work after a deterministic failure. |

Run `lifecycle` independently when a long retrieval case fails. It does not
turn that failure into success, but allows idle-slot, cancellation and media
checks to establish their own evidence. Lifecycle uses a fixed 2048-record
resident prompt rather than requiring a completed near-limit calibration.

Fresh llama.cpp slots omit prompt counters until they have processed a
request. `lifecycle` and `prefill` therefore explicitly initialize all four
idle slots with versioned bounded marker requests before requiring occupancy
observations. These use reasoning off, seed 42, cache disabled and a 128-token
budget through the same gateway defaults. The following strict native probe
must report measured counters for every slot. Missing counters are never
invented as zero. This is test preparation inside `check`, not hidden
inference in `preflight` or the build. Lifecycle requires 18 cases and 21
requests, including these four initialization cases.

Saved gateway-run summaries use `paracetamol.llama-acceptance.v2`. Version 2
separates lifecycle coverage from history and makes both mandatory in `all`.
Earlier combined-history v1 results remain historical evidence; do not edit
their schema or treat them as complete v2 coverage. The new comparator
rejects them. Coding task and corpus identities have not been relaxed.
Short checks also stop at their first non-PASS case. A truncated strict
replay remains FAIL because natural completion is part of its oracle; it
does not receive the coding screen's output-ceiling REVIEW classification.

Calibration uses the native tokenizer with a finite adjustment budget and then
requires actual request work counts. Missing token/cache/slot observations,
unestablished depth or near-pool occupancy block the affected claim. The
history cold target is 247000 measured input tokens, with an initial ceiling
of 248024. Later history inputs must not exceed 258048, reserving the full
4096-token output budget in the 262144-token pool. Append turns preserve
complete assistant history and retrieve two disjoint sets of previously
unqueried original-record values plus their turn-specific marker; returning
only a marker or repeating an earlier assistant answer cannot pass.
The conditioning sequence is a maintained reproducer, not proof of a physical
cache span or fast-kernel activation. Four launched workers alone do not prove
overlap or throughput. Trace affected kernels separately after correctness
gates; numerical and matcher tests cannot detect every silent slow fallback.

## Fixed diagnostic controls

`prepare-control` preserves two deliberately changed source controls, not
production options. `mmq-sum` removes the temporary HIP activation-sum
compatibility policy; this does not assert that upstream arithmetic is wrong.
`qsa-host-span` narrowly reduces the host matcher span while retaining the
normal HIP backend and precision. Both require the exact reviewed production
source/owning-file guards. A future refresh needs deliberate control review,
not automatic replacement of hashes or relaxation until the control builds.

Prepare and build one control at a time. The following example selects
`mmq-sum`; repeat with `CONTROL=qsa-host-span` for the other control:

```bash
CONTROL=mmq-sum
"$CHECKER" prepare-control --control "$CONTROL" \
  --out "build/control-$CONTROL-recipe"
podman build --pull=never --layers --target llama-acceptance-control-builder \
  -f "build/control-$CONTROL-recipe/Containerfile" \
  -t "localhost/paracetamol-experiment:control-$CONTROL-builder" .
CONTROL_BUILDER_IMAGE=$(podman image inspect --format '{{.Id}}' \
  "localhost/paracetamol-experiment:control-$CONTROL-builder")
mkdir "build/control-$CONTROL-export"
EXPORT_ID=$(podman create --pull=never --network=none --read-only \
  --cap-drop=ALL --security-opt no-new-privileges \
  --entrypoint /bin/false "$CONTROL_BUILDER_IMAGE")
podman container inspect "$EXPORT_ID"
podman cp "$EXPORT_ID":/opt/control/source-tree.txt \
  "build/control-$CONTROL-export/source-tree.txt"
podman rm "$EXPORT_ID"
CONTROL_TREE=$(cat "build/control-$CONTROL-export/source-tree.txt")
podman build --pull=never --layers --target llama-acceptance-control \
  --build-arg "ACCEPTANCE_CONTROL_TREE=$CONTROL_TREE" \
  -f "build/control-$CONTROL-recipe/Containerfile" \
  -t "localhost/paracetamol-experiment:control-$CONTROL" .
CONTROL_IMAGE_ID=$(podman image inspect --format '{{.Id}}' \
  "localhost/paracetamol-experiment:control-$CONTROL")
```

Check each command and exact created container before proceeding. The second
build requires the actual tree extracted from the first builder; a remembered
tree or omitted `ACCEPTANCE_CONTROL_TREE` is rejected. Keep both image IDs and
export `/opt/control/evidence/` from an exact unstarted final-image container
using the same create/inspect/copy/remove procedure. Its source diff, compiler,
CMake, installed-library and build evidence must show the intended mutation
and only the selected payload changed. A built control is not yet a runtime
rejection or a measured slow path.

The ordinary gateway has no image-override flag. To serve a control without
touching normal tags or the checkout binary, use the existing compile-time
image namespace. Set `NORMAL_IMAGE` to the **current** normal llama.cpp image
reference from `internal/application/registry.go`/normal image inspection; do
not copy a dated version string. Keep product, state and ownership labels
unchanged. On Linux amd64:

```bash
CONTROL_NAMESPACE="localhost/paracetamol-acceptance-$CONTROL"
CONTROL_TAG="$CONTROL_NAMESPACE:${NORMAL_IMAGE##*:}"
podman tag "$CONTROL_IMAGE_ID" "$CONTROL_TAG"
CONTROL_BIN_DIR="$PWD/build/linux-amd64/control-$CONTROL-bin"
make -B IMAGE_NAMESPACE="$CONTROL_NAMESPACE" \
  BIN_DIR="$CONTROL_BIN_DIR" BIN="$CONTROL_BIN_DIR/paracetamol" build
sha256sum "$CONTROL_BIN_DIR/paracetamol"
```

This remains a normal CGO build. Do not override `PRODUCT_ID`, use the normal
`BIN` path, retag a production image or change system configuration. Record
the isolated controller hash, Git revision/dirty state and exact invocation
in private campaign notes before testing. Do not append files to an already
completed evidence directory.

The control shares the normal gateway's control socket/state namespace. Have
the owner stop any existing gateway first; never stop an unrelated workload.
With the inference prerequisites above and explicit reviewed `PROFILE` and
`RENDER_NODE`, start the isolated controller in another terminal:

```bash
"$CONTROL_BIN_DIR/paracetamol" --no-config run gateway \
  --application llama-cpp --profile "$PROFILE" --render-node "$RENDER_NODE" \
  --data-dir "$DATA_DIR" --listen 127.0.0.1 --port 7455 \
  --backend rocm --models-max 1 --slots 4 --statistics=false
```

This is the same production gateway/sampling path, not a control proxy. Warm
the selected `MODEL`, inspect its exact gateway-owned container, set
`CONTAINER_ID` and `IMAGE_ID=$CONTROL_IMAGE_ID`, and run the explicit diagnostic
check. For MMQ use `--control mmq-sum --suite short`; for QSA use
`--control qsa-host-span --suite prefill` and the same predeclared
`--prefill-regression-percent` as its normal baseline. Supply the ordinary
gateway/data/model/image/container and fresh output flags shown above.

Match baseline/control content, effective policy, fixtures and same-boot
conditions. Repeat measured QSA arms in counterbalanced order and use the
offline comparison. Controls can establish a rejected regression only when
the relevant oracle or observed performance/conditioning gate actually
detects it. An unexpectedly passing or inconclusive control is retained and
investigated, not renamed a qualified gate. Explicit `--control` runs and
comparisons never qualify a normal source update: their role is diagnostic,
and comparison remains REVIEW even if their selected cases pass. Stop only
the isolated gateway you launched and retain its source/image/controller
identities alongside the evidence.

## Coding attempts and independent oracles

The public tasks are newly versioned pure algorithms, not the retired Pi
tasks or an agent/Maki evaluation. Go merges sorted `int64` streams into
unique fresh storage. Python coalesces overlapping closed intervals, including
shared endpoints but not positive gaps. Read their exact tracked prompts;
similar historical task names do not imply identical contracts.

Each task first uses xhigh, seed 42, cache disabled, omitted gateway-owned
samplers and its fixed output budget. A complete response must contain only
one bounded JSON `code` string before execution. A miss retains that attempt.
The predeclared follow-up, only after a miss, is one repair with complete
assistant history and bounded actual verifier feedback when available, plus
independent fresh prompts at seeds 1234 and 2026. No reference implementation
is sent to the model. A later pass never replaces an earlier miss or upgrades
the campaign to PASS. Do not increase budgets, pick favorable seeds or weaken
tests after observing a failure.

Keep the runner's result separate from the source-update decision. An
isolated coding miss recovered under that fixed protocol is different from
persistent failure. A maintainer may document an inherited limitation when
matched baseline/candidate evidence shows no deterioration, without changing
REVIEW to PASS. A persistently failing baseline cannot discriminate an
upgrade. This judgment cannot waive the other acceptance gates. Follow the
[coding review policy](../../docs/testing-and-release.md#bounded-coding-quality-screen).

Oracles independently compute expected values and check deterministic edge,
property and ownership cases. They do not prove the requested asymptotic
complexity or broad coding ability. Tests and solutions are public reviewer
material, withheld from model requests, not secret. See the
[scenario](internal/scenarios/PROVENANCE.md) and
[coding](internal/coding/PROVENANCE.md) provenance records. Newly authored
fixtures use the project's [BSD-3-Clause license](../../LICENSE); review
provenance and any third-party licensing before importing replacements.

## Evidence, comparison and decisions

Keep a campaign ledger in private experiment notes. Begin each applicable row
as BLOCKED and record its commands, immutable inputs, expected/observed case
counts, evidence paths and limitations. Preparation or a successful process
exit does not establish that a GPU case actually ran.

| Required coverage | Supplied by this kit |
| --- | --- |
| Image/source/runtime closure, CPU CLI/router startup and offline content | Preparation and identity checks only; retain the separate image/startup checks. |
| Native numerical, state, poisoned-reset and kernel-activation gates | Matching-source compilation for selected probes, not execution of the complete numerical/trace matrix. CPU reset checks are not GPU reset coverage. |
| Plain and greedy DFlash2 protocol, lifecycle, coding, history and prefill | Explicit `check --suite all` for each model/image arm, with individual outcomes retained. |
| Matched repeated performance | `compare` checks saved counterbalanced observations, not an isolated rate. |
| Responses API, direct CLI/router generation and lifecycle | Separate integration checks from the source-update procedure. The kit's inference transport uses Chat Completions. |
| Real overlapping-generation throughput | Separate measurement. Four worker markers check isolation, not sustained overlap or aggregate throughput. |
| Other affected backends and hardware classes | Separate applicable hardware acceptance. The frozen kit policy targets a sufficiently capable `gfx1151` host. |

Finish with a separate maintainer decision covering every applicable row.
Explain non-applicable rows and keep unavailable hardware or unimplemented
required checks visibly BLOCKED/deferred. Neither `all` nor `compare` emits a
whole-campaign approval. The
[source-update procedure](../../docs/testing-and-release.md#llamacpp-source-update-acceptance)
owns that wider contract.

Private evidence includes requests, raw JSON/SSE responses, full assistant
objects, typed correlated gateway reports, native slot snapshots, image/source
and content identities, generated code and grader output. Request reports
retain gateway instance/inventory identities, sampler source/value, completion
evidence, cached/new work and native prompt/generation timings. Missing fields
stay absent; they are never converted into zeroes. Pre-header cancellation
uses opaque session correlation and existing bounded metadata to recover the
canceled request, not a guessed ID. Partial responses and failed attempts stay
retained. Cancellation is verified only with matching canceled-report policy,
identity/session and successfully saved evidence; an ordinary context-canceled
error alone cannot pass it. No inference or response-header timeout is imposed;
metadata probes and generated-code execution are bounded.

Use repeated baseline/candidate runs in counterbalanced order, such as ABBA,
under identical fixture hashes, model bytes, template, runtime policy, device,
hardware observations and cache-conditioning procedure. Predeclare a
`--prefill-regression-percent` tolerance before candidate timing, based on
baseline repeatability and the regression size of concern; there is no
automatic default. `prefill`/`all` require that declaration. Compare saved
summaries offline with repeated `--baseline` and `--candidate` paths. At least
two usable observations per arm are needed for a timing decision; insufficient
or equivocal evidence is REVIEW, not a speedup or acceptance claim. Changed
work counts or other uncontrolled inputs make results incomparable. Do not
sum per-request token rates or time a diagnostic image as the normal image.

Comparison also requires matching private same-boot identities. The boot hash
is retained only with local evidence, not a persistent public machine ID.
Rebooting between arms is not a matched comparison even if the kernel version
string is unchanged. The checker does not reconfigure a host to repair a
mismatch.

For example, after running plain baseline/candidate/candidate/baseline with
the same declared tolerance and distinct output paths:

```bash
"$CHECKER" compare \
  --baseline build/llama-baseline-plain-1 \
  --baseline build/llama-baseline-plain-2 \
  --candidate build/llama-candidate-plain-1 \
  --candidate build/llama-candidate-plain-2
```

Repeat the comparison separately for the DFlash2 arm. `compare` reads and
validates completed evidence directories; it performs no inference and
changes none of their files.

`PASS` means only that every required case in the selected operation has
complete passing evidence. `FAIL` records a deterministic protocol, policy or
answer-oracle failure. `BLOCKED` records missing prerequisites or required
observations. `REVIEW` preserves bounded coding misses, coding output ceilings
and unresolved performance comparisons. It does not establish an engine defect.
Only PASS exits zero. A completed non-PASS operation exits two, execution/setup
errors exit one and interruption exits 130. Read individual cases rather than
treating every nonzero result as the same failure.

A full source update still needs matching-source native fixtures, numerical
checks, all required production-path suites/controls, repeated performance
comparisons and applicable hardware acceptance. Record unavailable hardware
or required gates as BLOCKED/deferred. A targeted `short`, `lifecycle`,
`coding`, `history` or `prefill` PASS cannot silently replace the missing
coverage. If the baseline fails or varies, retain it and narrow the conclusion; a candidate coding miss
is not automatically a successful-baseline-to-candidate regression.

Do not hardcode a current candidate image ID or arbitrary one-shot prose into
oracles. Preserve the recovered thinking-off literal's exact semantic value
and surrounding-whitespace tolerance, while general tool/code/history cases
use their declared structured/value contracts. Fixture changes require review
and a new identity, not automatic hash regeneration. Preserve old failed
results and historical oracles when defining successors.

Run ordinary tests and `self-test --source-only` after a fresh clone without
old `build/` artifacts. Separately run the real grader self-test and a known-bad
engine/control campaign before claiming that the full gate is runtime
qualified. Source tests and fake HTTP/Podman tests alone are not that evidence.
Back up irreplaceable private results before `make clean`; `build/` is not a
backup, and deleting it must not delete the versioned test definitions.

The [initial qualification record](../../docs/research/llama-acceptance-kit-qualification.md)
distinguishes exercised paths from failed or deferred coverage. It is dated
evidence, not permission to omit a required gate in the next source update.
